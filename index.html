macOS 一直没有这个开关。DockClickMin 用系统原生 API 把它补上：点一下收起，带 genie 动画飞进图标；再点一下还原。

macOS 13.0+ 通用二进制 x86_64 / arm64 菜单栏常驻 · 无 Dock 图标 MIT
↓ 下载 Release 查看源码

为什么必须自己写

点 Dock 图标只有两个原生语义：把应用激活到前台；已在前台则什么都不做。系统设置里唯一相关的一项是「将窗口最小化至应用程序图标」，但那决定的是窗口最小化后去哪，不是点图标收起。

操作WindowsmacOS（原生）
点任务栏 / Dock 图标（非前台）切换到该应用切换到该应用
再点一次（已在前台）最小化到任务栏无反应
点已最小化的图标还原还原所有窗口

有人会想到在 app 内实现 applicationShouldHandleReopen。这条路走不通——app 已在前台时，Dock 根本不发 rapp 事件，那个回调不会被调用。所以只能从系统层监听点击。

原理：三步

不注入、不 hook、不修改任何系统文件。只读 Dock 的辅助功能树 + 监听鼠标事件。

1 读 Dock 图标矩形 AXUIElement 遍历程序坞的辅助功能树，拿到每个图标的实时矩形与 bundle id。放大动画、图标增减都自动跟随。
→
2 监听左键按下 / 抬起 CGEventTap 在会话层看鼠标事件。按下时记住「当时的前台 app」，抬起时判断落点是否仍在同一个图标内。
→
3 是同一个 ⇒ 收起 只有「点的就是当前前台 app」才动手；点别的图标一律放行，交给系统正常切换。 
// 核心判据（简化）
let tile = dockTiles.first { $0.rect.contains(point) }   // 落在哪个图标上
guard tile.pid == frontmostPIDAtMouseDown else { return } // 点的是不是当时的前台 app
collapse(tile)                                            // 收起它

功能

每一条都在真机上验证过，日志里能看到对应证据。

原生最小化动画

按窗口自己的黄色按钮，genie 动画由 WindowServer 出——和手点按钮完全同一条路径，不是伪造的过渡。

点第二下还原

窗口已全部最小化时主动放行，交给系统原生的「点图标恢复所有窗口」。收起和还原都有动画。

三级回退

AX 的 .success 只代表消息投递成功。按按钮无效的 app（如 QQ），自动降级到 ⌘M，再降级到直接置最小化属性。

不抢原生操作

带 ⌘/⌥/⌃/⇧ 点、图标内拖拽、应用无窗口——全部放行。⌥-click 隐藏其他等行为照旧。

启动台单独处理

启动台不是普通 app：覆盖层由程序坞自己绘制（layer 27/29），没有独立进程。点图标时吞掉点击并发 Esc 关闭。

开机自启

默认开启。写 ~/Library/LaunchAgents 的 plist，登录时 launchd 自动加载；app 移动后路径自愈。

收起方式

菜单里可切换。默认是最小化——因为只有它带原生动画。

方式实现动画
最小化窗口（默认）三级回退：按黄色按钮 → ⌘M → 置 AXMinimized✅ 前两级有
隐藏整个应用NSRunningApplication.hide()，等同于 ⌘H❌ 瞬时

动画样式跟随 系统设置 › 桌面与程序坞 ›「最小化窗口使用」。想确认当前是哪种：

defaults read com.apple.dock mineffect      # genie（精灵）| scale（缩放）

安装

从 Release 下载 zip，解压后拖进「应用程序」，然后授权辅助功能。

  1. 解压并放到「应用程序」

    下载 DockClickMin-<version>.zip，双击解压，把 DockClickMin.app 拖进「应用程序」文件夹。

  2. 首次打开放行 Gatekeeper

    本包是 ad-hoc 签名、未做 Apple 公证，首次打开会被拦。见下方提示，按新系统的正确路径放行。

  3. 授予辅助功能权限

    弹窗「DockClickMin 想要控制这台电脑」→ 打开系统设置 → 隐私与安全性 › 辅助功能 → 打开 DockClickMin 的开关。授权后菜单栏出现图标，状态显示「监听中 · N 个图标」。

⚠︎
macOS 15 Sequoia 起，「右键 → 打开」这条绕过通道已被 Apple 移除，弹窗里不会再出现「打开」按钮。正确路径是：
双击被拦 → 点「完成」→ 系统设置 › 隐私与安全性 › 安全性 → 点「仍要打开」→ 输密码 → 再点「打开」。

也可以自己编译（需要 Xcode Command Line Tools）：

git clone https://github.com/GeekAudio/DockClickMin.git
cd DockClickMin
./build.sh run        # 编译 + ad-hoc 签名 + 启动

已知限制

说清楚边界，比只说优点有用。

  • 必须授权辅助功能。要读 Dock 的辅助功能树、要监听鼠标事件，这是硬性前提，无法绕过。
  • 重编译会掉授权。ad-hoc 签名没有稳定身份，TCC 记的是 cdhash；每次重新编译后要在辅助功能里把开关关掉再打开。
  • Dock 自动隐藏时有约 1 秒延迟。图标矩形缓存 1 秒刷新一次，Dock 还没升起来时坐标在屏幕外。
  • 部分 app 不认 AX 动作。实测 QQ 对「按最小化按钮」返回 success 却不执行，靠第二、三级兜底；兜底级没有动画。
  • 只处理「点当前前台应用的图标」。点别的应用图标是正常切换，不会收起——这是刻意设计，避免误伤。

技术细节

踩过的坑，写给需要改这个工具的人。

为什么重编译后辅助功能授权会失效？

ad-hoc 签名没有开发者身份，TCC 只能用 cdhash 认人。可以从授权库里把它解出来对照：

sqlite3 "/Library/Application Support/com.apple.TCC/TCC.db" \
  "select hex(csreq) from access where client='com.geekaudio.DockClickMin' \
   and service='kTCCServiceAccessibility';" | xxd -r -p > /tmp/c.bin
csreq -r /tmp/c.bin -t
#   cdhash H"83b7776a..." or cdhash H"c166ca8a..."    ← 旧二进制（两个架构各一条）
codesign -d --verbose=4 DockClickMin.app 2>&1 | grep ^CDHash
#   CDHash=078f2ebd...                                ← 新二进制，不在列表里 ⇒ 拒绝

要彻底免掉这一步，得换成自签名证书签名（designated requirement 与 cdhash 解耦），并把它加入系统信任。

为什么启动台要单独处理？

macOS 26 把启动台换成了 /System/Applications/Apps.app（com.apple.apps.launcher，LSUIElement）。它不是普通应用：

  • 图标在 Dock 上解析出来的 pid 是 -1，因为它平时不运行；
  • 打开后，全屏覆盖层由程序坞进程自己绘制——实测程序坞会多出 layer=27 和 layer=29 两个全屏窗口，关闭时只剩 layer=20。

所以「关掉一个进程」这条路不存在。做法是：点图标时把这一次点击吞掉（不让程序坞处理），同时发 Esc 给程序坞，用「程序坞有没有 layer ≥ 26 的窗口」判断是否真的关掉了。

权限授权后为什么要重启进程？

AXIsProcessTrusted 的结果会被进程缓存：授权之前启动的实例不会自动变可信，事件监听也就不会建立。

本工具的做法是每 2 秒复查一次权限，一旦通过就自己建立监听——所以授权后不需要手动重启，最多等 2 秒。

只给自己的 app 加这个功能，需要这么重吗？

不需要，但只在「app 不在前台时点图标」生效：

func applicationShouldHandleReopen(_ sender: NSApplication, hasVisibleWindows flag: Bool) -> Bool {
    guard flag else { return true }
    for w in NSApp.windows where w.isVisible && !w.isMiniaturized && w.canBecomeMain {
        w.miniaturize(nil)      // 或 NSApp.hide(nil)
    }
    return false
}

要「已在前台也能收起」，就必须像本工具一样上 CGEventTap + 辅助功能 API，代价是权限申请和常驻进程。
